# Assignment System Design and UX/UI

เอกสารนี้สรุปแนวทางออกแบบระบบมอบหมายงานของ Juristic Care V2 สำหรับใช้เป็นเกณฑ์พัฒนา, ทดสอบใน Pre-Production, และตรวจรับก่อนส่งต่อ Production

## เป้าหมายของระบบ

ระบบมอบหมายงานต้องช่วยให้นิติบุคคลรับเรื่อง, แยกประเภท, มอบหมายผู้รับผิดชอบ, ติดตามสถานะ, ตรวจรับงาน, และเก็บหลักฐานได้ในที่เดียว โดยเน้นการใช้งานจริงรายวันมากกว่าหน้าแสดงผลเชิงประชาสัมพันธ์

หลักการสำคัญ:

- เห็นงานที่ต้องทำก่อนเสมอ เช่น งานใหม่, งานเกินกำหนด, งานรอตรวจรับ
- มอบหมายงานได้เร็วและลดความผิดพลาดจากการเลือกคนผิดทีม
- ผู้ปฏิบัติงานเห็นเฉพาะสิ่งที่เกี่ยวข้องกับตนเอง
- ทุกการเปลี่ยนสถานะต้องมี log ตรวจสอบย้อนหลัง
- ก่อนเปลี่ยน Production ต้องผ่าน Pre-Production และมีขั้นตอนยืนยัน

## บทบาทผู้ใช้งาน

- Admin: จัดการผู้ใช้, สิทธิ์, ทีมงาน, ตรวจรับงาน, export ข้อมูล, และอนุมัติขั้นตอนสำคัญ
- Co-admin / Juristic: รับเรื่อง, คัดกรอง, มอบหมายงาน, ติดตามงาน, ตรวจสอบหลักฐาน
- Technician / Housekeeping / Security / Gardener: รับงาน, อัปเดตสถานะ, แนบหลักฐาน, ส่งงานตรวจรับ
- Resident / Owner: แจ้งงาน, ติดตามสถานะ, ยืนยันปิดงานด้วย PIN ในกรณีที่กำหนด

## Workflow มอบหมายงาน

1. รับเรื่อง
   - สร้างงานจากฟอร์ม, เจ้าหน้าที่, หรือข้อมูลนำเข้า
   - ระบุหมวดหมู่, อาคาร/ห้อง, ความเร่งด่วน, รายละเอียด, และหลักฐาน

2. คัดกรอง
   - ตรวจความครบถ้วนของข้อมูล
   - เลือกทีมที่เหมาะสมตามประเภทงาน
   - กำหนด SLA หรือวันครบกำหนด

3. มอบหมาย
   - เลือกผู้รับผิดชอบหลัก
   - เลือกผู้ช่วยหรือทีมร่วมได้เมื่อจำเป็น
   - ระบบควรแสดงภาระงานปัจจุบันของแต่ละคนเพื่อช่วยตัดสินใจ

4. ปฏิบัติงาน
   - ผู้รับผิดชอบเปลี่ยนสถานะเป็นกำลังดำเนินการ
   - เพิ่มบันทึกความคืบหน้าและรูปหลักฐาน
   - หากติดปัญหา ต้องระบุเหตุผลและผู้ที่ต้องตัดสินใจต่อ

5. ส่งตรวจรับ
   - เมื่อเสร็จงาน ผู้รับผิดชอบส่งงานพร้อมหลักฐาน
   - งานเข้าสถานะรอตรวจรับ

6. ยืนยันปิดงาน
   - งานที่ต้องยืนยันจากผู้อยู่อาศัยให้ใช้ PIN
   - งานภายในหรือกรณีที่ Admin ตรวจรับแทนต้องมีเหตุผลและ log ชัดเจน

7. ปิดงานและบันทึกประวัติ
   - เก็บผู้ปิดงาน, เวลา, หลักฐาน, หมายเหตุ, และประวัติการเปลี่ยนแปลง

## UX/UI หลัก

### Dashboard งาน

- ใช้มุมมองแบบ board หรือ list ที่ scan ได้เร็ว
- แสดงกลุ่มสถานะ เช่น งานใหม่, มอบหมายแล้ว, กำลังดำเนินการ, รอตรวจรับ, ปิดแล้ว
- มีตัวกรองตามอาคาร, ห้อง, ทีม, ผู้รับผิดชอบ, ความเร่งด่วน, และวันครบกำหนด
- งานเกินกำหนดต้องมองเห็นเด่นชัดโดยไม่รบกวนงานปกติจนเกินไป

### Job Card

ข้อมูลที่ควรแสดงใน card:

- เลขงานหรือรหัสอ้างอิง
- ประเภทงานและความเร่งด่วน
- ห้อง/พื้นที่
- ผู้รับผิดชอบ
- สถานะล่าสุด
- วันครบกำหนด
- จำนวนหลักฐานหรือบันทึกความคืบหน้า

Card ไม่ควรยาวเกินไป รายละเอียดลึกควรอยู่ใน modal หรือหน้ารายละเอียด

### Assignment Panel

ส่วนมอบหมายงานควรอยู่ในรายละเอียดงานและใช้งานได้ด้วยขั้นตอนสั้น:

- เลือกทีม
- เลือกผู้รับผิดชอบ
- ดูภาระงานของผู้รับผิดชอบก่อนยืนยัน
- ใส่หมายเหตุการมอบหมาย
- ยืนยันและสร้าง audit log ทันที

### Detail Modal

หน้ารายละเอียดงานควรแยกข้อมูลเป็นส่วนชัดเจน:

- รายละเอียดงาน
- ผู้แจ้ง / ห้อง / ช่องทางติดต่อ
- ผู้รับผิดชอบและทีม
- Timeline และ log
- หลักฐาน
- ปุ่ม action ตามสิทธิ์ผู้ใช้

ปุ่ม action ควรแสดงเท่าที่ผู้ใช้ทำได้จริง เพื่อลดความสับสนและลดความเสี่ยงด้านสิทธิ์

## Design Guidelines

- ใช้ layout แบบ operational dashboard: ข้อมูลแน่นแต่ไม่รก
- Sidebar ใช้สำหรับ navigation หลัก และเมนูบัญชีควรเปิดเป็น flyout ด้านข้างเพื่อไม่ดัน layout
- ใช้สีสถานะอย่างมีความหมาย เช่น ใหม่, ด่วน, เกินกำหนด, รอตรวจรับ
- ปุ่มสำคัญต้องมี label ชัดเจน และ action อันตรายต้องมี confirmation
- ข้อความบนหน้าจอต้องเป็นภาษาที่ผู้ดูแลอาคารเข้าใจง่าย ไม่ใช้ศัพท์เทคนิคเกินจำเป็น
- Mobile ต้องรองรับการดูงาน, อัปเดตสถานะ, และแนบหลักฐานได้สะดวก

## Permission and Safety

- การมอบหมาย, เปลี่ยนผู้รับผิดชอบ, ปิดงาน, และตรวจรับงานต้องตรวจสิทธิ์เสมอ
- Admin preview หรือ view-as ต้องไม่ให้สิทธิ์เกินกว่าที่กำหนด
- Export ข้อมูลพนักงานและงานควรจำกัดเฉพาะ role ที่ได้รับอนุญาต
- ทุก action สำคัญต้องบันทึก actor, เวลา, role, ค่าก่อนหน้า, และค่าหลังเปลี่ยน
- ห้ามให้ Pre-Production เขียนทับข้อมูล Production

## Pre-Production UX Checklist

ก่อนอนุมัติส่งต่อ Production ให้ทดสอบอย่างน้อย:

- สร้างงานใหม่และเห็นใน board/list ถูกต้อง
- มอบหมายงานให้แต่ละทีมได้ถูกต้อง
- ผู้รับผิดชอบเห็นงานของตนเอง
- ผู้ไม่มีสิทธิ์ไม่เห็นปุ่มที่ไม่ควรใช้
- เปลี่ยนสถานะงานครบ flow ตั้งแต่ใหม่ถึงปิดงาน
- แนบหลักฐานและดูหลักฐานย้อนหลังได้
- งานที่ต้องใช้ PIN ปิดไม่ได้ถ้า PIN ผิด
- Admin ตรวจรับแทนได้เฉพาะกรณีที่มีสิทธิ์และมี log
- Filter/search ไม่ทำให้จำนวนงานผิด
- Mobile แสดง card, modal, และเมนูบัญชีโดยไม่ซ้อนทับกัน

## Production Readiness Notes

รายการที่ต้องยืนยันก่อนส่ง Production:

- Pre-Production ผ่าน smoke test และ UX checklist
- ไม่มี demo password หรือข้อมูลตัวอย่างปะปนกับข้อมูลจริง
- Supabase URL และ key ของ Production ไม่ถูกใช้ใน Pre-Production
- Environment variables แยกระหว่าง Pre-Production และ Production
- ขั้นตอนอนุมัติส่งต่อ Production ต้องใช้ Bit code ตาม runbook
- มี rollback plan และผู้รับผิดชอบอนุมัติชัดเจน
